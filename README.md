# ComfyPipeline 2

[comfy-pipeline](../comfy-pipeline) のスマホ・タブレット向け版。PC で動かし、Tailscale 経由でスマホから開く。
生成はキューに入れた時点で ComfyUI が進めるので、スマホを閉じても止まらない。

## 画面

| タブ | できること |
| --- | --- |
| 生成 | 一括キューのセットを選び(**複数セット可**。既定サイズは「設定」で決める)、LoRA・身体・セットごとのシーンと、実行するプリセットを決める。`%%変数%%` の入力(**タグ辞書からサジェスト**。値は「既定にする」で保存)、1枚テスト生成、保留キューへの追加。各項目の鉛筆でプリセット・変数・LoRA・一括キューのプリセットを編集 |
| キュー | **保留中(まだ始まっていない)** を「開始」で一斉に送る。実行中は途中画像と進捗、やり直し(同じプロンプト/引き直し)、中止。待機中の取り消し、完成画像の確認 |
| ギャラリー | フォルダ → プリセット名単位のグループ(選択済み/全枚数と、ジャンプできる一覧つき)。サイズはスライダー。**タップでリリース選択の切り替え、長押しで全画面スワイプ**。**「入れ替え」で、同じプリセットの2枚を選んでファイル名(連番)を入れ替え**(メタデータ・リリース用コピー・モザイク・v1の保管庫は画像についていく)。ビューアでプロンプトを編集して再生成(やり直し・中止つき)、削除。**右の一覧(スマホは「一覧」)の「＋」で、そのプリセットを同じ構成のままあと n 枚追加**(ランダム部分と seed は1枚ごとに引き直し。生成中は「ランダムも入れ替えて作り直し」「別シードで作り直し」「残りを中止」) |
| モザイク | ギャラリーでリリース選択した画像(`<フォルダ>_release`)に、**縮小とモザイクを一括で**かける(v1 の automosaic をそのまま使う)。1枚ずつ、**指でなぞってモザイクを足す**・**モザイクなしに差し戻す**・保存。仕上がったら「リリース用フォルダへ連番コピー」 |
| リリース | リリース用フォルダの作品ごとに、画像の確認、**Pixiv用の画像を選ぶ**(最大9枚)、**PDF・ZIP の作成**、**Pixivアップロード用ファイルセット**(投稿用画像 + Booth 告知の3×3タイル画像)の作成とダウンロード |
| 状態 / 設定 | VRAM・メモリ・モデルの解放 / チェックポイント・既定サイズ・サンプラーなど(スマホでは右上のメニューから) |

追加した生成は **保留** にたまり、「キュー」タブの「開始」を押すまで ComfyUI へは送られない。
テスト生成と再生成だけは、待たずに待機列の先頭へ割り込ませる。

画面幅 900px 以上(タブレット横向きなど)では、下のタブバーが左のレールに替わり、2列表示になる。

## リリース作業の流れ

1. ギャラリーでリリースに選ぶ
2. モザイクタブで一括処理し、手で調整する
3. 「リリース用フォルダへコピー」(作品名・グループ名を入力。前戯・本番などグループごとに繰り返す)
4. リリースタブで Pixiv 用の画像を選び、PDF・ZIP・Pixiv用セットを作ってダウンロードする

- リリース用フォルダの形: `<ルート>\YYYYMM\YYYYMMDD_作品名\グループ名\NN.jpg`(既定のルートは `X:\`)。
- 出力は `<ルート>\YYYYMM_PDF\` に作る。元の画像には書き込まない。
- PDF・ZIP・Pixiv用セットは `folder-to-pdf` スキルと同じ Python スクリプトを使う(`scripts/release/`)。
  スキル側を直したらここも合わせる。差分は `--pick`(Pixiv用画像の手選び)・`--no-pdf`・設定場所の環境変数化。
- 依存: Python(Pillow, segno)、Windows のフォント(メイリオ)。モザイクは v1 の `automosaic/`(venv とモデル込み)。
- 場所は環境変数で変えられる: `RELEASE_ROOT_DIR`(既定は v1 の設定 `releaseRootDir`、無ければ `X:\`)、`AUTOMOSAIC_DIR`。

## ホーム画面に追加(PWA)

`public/manifest.json` とアイコン(`public/icons/`)で、スマホ・タブレットのホーム画面に全画面アプリとして追加できる(縦横どちらの向きでも使える)。

- **iPhone / iPad**: Safari で開き「共有 → ホーム画面に追加」。HTTP のままでも追加できる。
- **Android / Chrome**: 「アプリをインストール」を出すには **HTTPS** が必要。Tailscale の IP(`http://100.x.x.x`)は HTTP なので、
  `tailscale serve` で https の MagicDNS 名(`https://<PC名>.<tailnet>.ts.net`)を使う:

  ```bash
  HOST=127.0.0.1 pnpm start      # アプリは PC 自身にだけ待ち受ける
  tailscale serve --bg 3100      # tailnet 内にだけ HTTPS で公開(インターネットには出ない)
  ```

  HTTPS で開くとサービスワーカー(`public/sw.js`)も有効になり、VPN が切れていて PC に届かないときは、
  真っ白なエラーの代わりに確認事項を出す(`public/offline.html`)。API・画像はキャッシュしない。

## 起動

デスクトップの `ComfyPipeline-Start.bat` で、ComfyUI と comfy-pipeline2(と v1)をまとめて起動できる。
コードを更新したあとも、もう一度押せば、古ければ自動で再ビルドして再起動する。手で起動するなら:

```bash
pnpm install
pnpm dev          # 開発
pnpm build && pnpm start   # 常用
```

`scripts/serve.mjs` が **Tailscale のアドレス(100.64.0.0/10)だけ**で待ち受ける。このアプリには認証がなく、
削除や生成を誰でも実行できるため LAN 全体(0.0.0.0)には公開しない。Tailscale が見つからないときは
127.0.0.1 のみ。`HOST` / `PORT`(既定 3100)で上書きできる。

## v1 との関係

- プリセット・LoRA・固定タグ・ネガティブ(`data/library/*.json`)、ComfyUI の URL、出力フォルダ、保存形式は
  v1 の `.comfy-pipeline.json` と `data/library` を共有する。APIキーなど秘密情報はこのリポジトリへコピーしない。
- 場所が違うときは環境変数 `COMFY_PIPELINE_DIR` / `COMFYUI_URL` / `OUTPUT_DIR` / `LIBRARY_DIR`。
- 生成画像は v1 のギャラリーと同じフォルダ・サイドカー JSON(`<file>.json`)・JPG 変換規則で保存する。
- `lib/comfy/workflow-builder.ts` `adetailer.ts` `lora-family.ts` `prompt-variables.ts` は v1 からのコピー。
  v1 側を直したらここも合わせる(将来はパッケージ化)。
- タグ辞書は v1 と同じ danbooru 日本語タグ CSV。サーバーが初回だけ取得して `data/tags.csv` にキャッシュし、`/api/tags?q=` で候補だけ返す。
- 追加生成(「＋」)は、v1 の画像ならメタデータの生成レシピ(`recipe`)、v2 の画像なら雛形(`template`。v2 が画像の隣の `.json` に残す)から構成を復元する。どちらも無い画像は、同じプロンプトを別シードで作る。
- このアプリ自身の状態(生成設定、未確定ジョブ、完成一覧)は `data/` に保存される(git 管理外)。
- プリセット等の編集は v1 と同じ `data/library/*.json` へ書く(検証→一時ファイル→rename)。v1 を同時に開いて保存すると、後に書いた方が勝つ。
